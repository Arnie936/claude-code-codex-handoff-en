Praxisleitfaden · Claude Code & Codex

Aufgaben sauber übergeben.

So wechselst du in einem laufenden Projekt zwischen Claude Code, Codex und anderen Coding-Agents — ohne Kontextverlust, doppelte Regeln oder chaotische Konfiguration.

Adapter-Prompt kopieren ↓ Dateien vergleichen

Kernidee Alle Agents arbeiten im selben Projektordner. Gemeinsame Projektinfos bleiben an einer Stelle; jeder Agent erhält nur einen passenden Adapter.

01 · Orientierung

Zwei Richtungen, zwei unterschiedliche Wege

Von Claude Code zu Codex gibt es eine offizielle OpenAI-Lösung. In Gegenrichtung ist aktuell ein bewusst aufgebauter Handoff im gemeinsamen Projektordner der pragmatische Weg.

● Offizielles Plugin
Claude Code → Codex

OpenAI stellt ein offizielles Plugin bereit, um Aufgaben aus Claude Code an Codex abzugeben. Das ist der direkteste Weg für diese Richtung.

Codex → Claude Code

Für die Gegenrichtung nutzt du den gemeinsamen Projektordner als Übergabepunkt. Bewährt sind die lokale CLI-Übergabe und eine strukturierte HANDOFF.md.

02 · Dateisystem

Claude Code und Codex im direkten Vergleich

Die Konzepte sind ähnlich, die Dateinamen und Ablageorte unterscheiden sich. Diese Zuordnung zeigt, was beim Übertragen angepasst werden muss.

Was du brauchst Claude Code Codex
Projektanweisungen CLAUDE.md AGENTS.md
Projekt-Konfigurationsordner .claude/ .codex/
Ablageort für Skills .claude/skills/<name>/SKILL.md .agents/skills/<name>/SKILL.md
Ablageort für Sub-Agents .claude/agents/<name>.md .codex/agents/<name>.toml
Agent-Dateiformat Markdown + YAML-Header TOML
Hooks, Berechtigungen, Umgebung .claude/settings.json .codex/config.toml
Persönliche / temporäre Abweichung CLAUDE.local.md AGENTS.override.md
Globale Konfiguration ~/.claude/ ~/.codex/ + ~/.agents/skills/
Benutzerweite Anweisungen ~/.claude/CLAUDE.md ~/.codex/AGENTS.md
Anweisungen für Unterordner Verschachtelte CLAUDE.md Verschachtelte AGENTS.md

03 · Praxis

Der robuste Handoff-Workflow

Dieser Ablauf funktioniert unabhängig davon, ob der nächste Agent Codex, Claude Code, Kimi, Hermes oder ein anderes lokales Coding-Tool ist.

01

Eine gemeinsame Wissensquelle festlegen

Behalte längere Projektregeln in CLAUDE.md. Lege AGENTS.md als schlanken Codex-Adapter an, der darauf verweist, Codex-spezifische Hinweise ergänzt und eine kurze Projektkarte enthält.

AGENTS.md → „Nutze CLAUDE.md als primäre Quelle für Projektwissen.“
02

Wichtige Skills vollständig übernehmen

Kopiere benötigte Skill-Ordner aus .claude/skills/ nach .agents/skills/. Halte jede SKILL.md zusammen mit ihren Skripten, Referenzen und Assets.

03

Sub-Agents ins passende Format übersetzen

Claude-Agenten liegen als Markdown-Dateien vor; Codex-Agenten als TOML. Übertrage die eigentlichen Anweisungen gezielt in developer_instructions, statt Dateien blind umzubenennen.

04

Bei langem Verlauf eine HANDOFF.md schreiben lassen

Der aktuelle Agent dokumentiert Ziel, Stand, Fehlversuche und nächste Schritte. Danach startest du den neuen Agenten im selben Projektordner.

„Lies die HANDOFF.md und arbeite ab dort weiter.“
05

Konfiguration und Geheimnisse trennen

Beginne mit einer minimalen, sicheren Konfiguration. Tokens, lokale Overrides und andere sensible Dateien gehören nicht in Git. Aktualisiere .gitignore, falls nötig.

04 · Copy & Paste

Kompletter Prompt für den Codex-Adapter

Diesen Prompt gibst du Claude Code in einem bestehenden Projekt. Er fordert zuerst Transparenz über geplante Änderungen und legt danach die Codex-kompatible Struktur an.

prompt-de.txt 
Ich habe dieses Projekt in Claude Code erstellt und möchte, dass es auch in Codex gut funktioniert.

Bitte prüfe das Projekt und erstelle eine Codex-Adapter-Struktur.

Erledige Folgendes:

1. Erstelle im Projektstamm eine AGENTS.md.
   - Nutze CLAUDE.md als Quelle für das Projektwissen.
   - Dupliziere lange Abschnitte nicht unnötig.
   - Erkläre, dass AGENTS.md der Codex-seitige Adapter ist.
   - Füge eine klare Projektübersicht hinzu.

2. Erstelle .codex/config.toml.
   - Beginne mit einer minimalen, sicheren Konfiguration.
   - Füge keine Geheimnisse hinzu.

3. Erstelle .agents/skills/.
   - Kopiere wichtige Claude-Skills aus .claude/skills/ nach .agents/skills/.
   - Halte jede SKILL.md und die zugehörigen unterstützenden Dateien zusammen.
   - Lege Skills nicht in .codex/skills/ ab.

4. Erstelle .codex/agents/ für alle wichtigen Claude-Agenten.
   - Claude-Agenten sind .md-Dateien in .claude/agents/.
   - Codex-Agenten sind .toml-Dateien in .codex/agents/.
   - Übertrage die Agent-Anweisungen in developer_instructions.

5. Aktualisiere .gitignore, falls nötig.
   - Halte lokale Overrides und Geheimnisse aus Git heraus.

Zeige mir vor dem Bearbeiten, welche Dateien du erstellen oder ändern möchtest.

05 · Wenn ein Chat feststeckt

Prompt für eine saubere HANDOFF.md

Nutze ihn im alten Chat, bevor du den Agenten wechselst. Das Ergebnis wird zur kompakten Übergabedatei für den nächsten Agenten.

handoff-prompt.txt 
Schreibe zusammen, was wir bisher gemacht haben, was nicht funktioniert hat und was als Nächstes verbessert werden muss. Speichere alles strukturiert in einer HANDOFF.md.

Die HANDOFF.md soll mindestens enthalten:
- Ziel und gewünschtes Endergebnis
- Aktueller Stand
- Bereits geänderte Dateien
- Wichtige technische Entscheidungen
- Fehlversuche und bekannte Probleme
- Offene Aufgaben in sinnvoller Reihenfolge
- Befehle zum Starten, Testen und Bauen
- Hinweise zu lokalen Abhängigkeiten oder benötigten Berechtigungen

Ändere bei dieser Zusammenfassung keine Projektdateien außer HANDOFF.md.

06 · Vor dem Wechsel

Die kurze Übergabe-Checkliste

Kontext

Eine Quelle, mehrere Adapter

Projektwissen nicht doppelt pflegen. Verweise von AGENTS.md auf die zentrale Wissensquelle.

Portierung

Struktur statt Dateikopie

Skills mit allen Hilfsdateien kopieren; Agent-Anweisungen in das jeweilige Format übersetzen.

Sicherheit

Keine Secrets in Git

Tokens, lokale Einstellungen und temporäre Overrides prüfen, bevor etwas committed wird.

  • Neuen Agenten im selben Projektordner starten.
  • CLAUDE.md und AGENTS.md sind konsistent.
  • HANDOFF.md beschreibt Stand und nächste Schritte.
  • Wichtige Skills enthalten ihre Skripte, Referenzen und Assets.
  • Lokale Konfiguration und Geheimnisse sind ignoriert.
  • Start-, Test- und Build-Befehle sind dokumentiert.
