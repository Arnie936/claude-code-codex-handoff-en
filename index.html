03 · In practice

A reliable handoff workflow

This workflow works whether the next agent is Codex, Claude Code, Kimi, Hermes, or another local coding tool.

01

Choose one shared source of project knowledge

Keep detailed project rules in CLAUDE.md. Create AGENTS.md as a small Codex adapter that points to it, adds Codex-specific guidance, and includes a brief project overview.

AGENTS.md → "Use CLAUDE.md as the primary source of project knowledge."
02

Copy important skills with all supporting files

Copy the skill folders you need from .claude/skills/ to .agents/skills/. Keep each SKILL.md together with its scripts, references, and assets.

03

Convert subagents to the right format

Claude agents use Markdown files; Codex agents use TOML. Transfer the actual instructions into developer_instructions rather than simply renaming files.

04

Have the agent write a HANDOFF.md for long conversations

The current agent documents the goal, progress, failed attempts, and next steps. Then start the new agent in the same project folder.

"Read HANDOFF.md and continue from there."
05

Keep configuration and secrets separate

Start with a minimal, secure configuration. Keep tokens, local overrides, and other sensitive files out of Git. Update .gitignore if needed.

04 · Copy & Paste

Complete prompt for the Codex adapter

Give this prompt to Claude Code in an existing project. It asks the agent to explain the planned changes first, then create a Codex-compatible structure.

prompt-en.txt 
I created this project in Claude Code and want it to work well in Codex too.

Please review the project and create a Codex adapter structure.

Do the following:

1. Create an AGENTS.md in the project root.
   - Use CLAUDE.md as the source of project knowledge.
   - Avoid unnecessarily duplicating long sections.
   - Explain that AGENTS.md is the Codex-side adapter.
   - Add a clear project overview.

2. Create .codex/config.toml.
   - Start with a minimal, secure configuration.
   - Do not add any secrets.

3. Create .agents/skills/.
   - Copy important Claude skills from .claude/skills/ to .agents/skills/.
   - Keep each SKILL.md together with its supporting files.
   - Do not put skills in .codex/skills/.

4. Create .codex/agents/ for all important Claude agents.
   - Claude agents are .md files in .claude/agents/.
   - Codex agents are .toml files in .codex/agents/.
   - Transfer the agent instructions into developer_instructions.

5. Update .gitignore if needed.
   - Keep local overrides and secrets out of Git.

Before editing, show me which files you plan to create or change.

05 · When a chat gets stuck

Prompt for a clear HANDOFF.md

Use this in the old chat before switching agents. The result becomes a concise handoff file for the next agent.

handoff-prompt.txt 
Summarize what we have done so far, what did not work, and what needs to improve next. Save everything in a structured HANDOFF.md.

HANDOFF.md should include at least:
- The goal and desired outcome
- Current progress
- Files already changed
- Important technical decisions
- Failed attempts and known issues
- Remaining tasks in a sensible order
- Commands to start, test, and build the project
- Notes on local dependencies or required permissions

When writing this summary, do not change any project files other than HANDOFF.md.

06 · Before switching

The short handoff checklist

Context

One source, multiple adapters

Keep project knowledge in one place. Point AGENTS.md to the central source.

Porting

Adapt the structure, not just the files

Copy skills with all their supporting files; convert agent instructions to the appropriate format.

Security

Keep secrets out of Git

Review tokens, local settings, and temporary overrides before committing anything.

  • Start the new agent in the same project folder.
  • CLAUDE.md and AGENTS.md are consistent.
  • HANDOFF.md describes progress and next steps.
  • Important skills include their scripts, references, and assets.
  • Local configuration and secrets are ignored by Git.
  • Start, test, and build commands are documented.
